# Feature inventory: GH Org Tool

This document lists every legacy feature, its status, and what Gitorgasm does with it. All paths are relative to the legacy repo `~/dev/legacy/gh-org-tool`. The detailed evidence is in [legacy-audit.md](./legacy-audit.md).

## 1. Legend

Status categories (one per feature):

| Status                                  | Meaning                                                                   |
| --------------------------------------- | ------------------------------------------------------------------------- |
| Fully implemented                       | Works end to end. No major defect found.                                  |
| Partially implemented                   | Some parts work. Visible parts are missing or wrong.                      |
| Implemented but architecturally fragile | Works in normal use. Fails under scale, concurrency, timeouts, or attack. |
| Broken or unreliable                    | Does not do what it claims, or fails often.                               |
| Deprecated                              | Still in the code, but dev-only, unused, or superseded.                   |
| Not implemented but clearly intended    | Schema, stubs, hooks, or docs show intent. No working code.               |
| Recommended future capability           | Not in legacy. Gitorgasm should add it.                                   |

Recommendations: **Preserve** (keep the behavior, port it), **Redesign** (keep the goal, change the design), **Remove** (do not carry over), **Postpone** (not in the first release).

Evidence labels: **V** = Verified by reading code or running a command. **I** = Inference. **A** = Assumption.

## 3. API route inventory

There are **38** route files (`AGENTS.md` says 37). **V**: `find app/api -name route.ts`.

Guard shorthand:

- **S** = `requireApiSession` or `getRequestSession` (Bearer header, then `gh_session` cookie → `auth_sessions`). `lib/api/server.ts:57-71`, `lib/auth/request-session.ts:18-33`.
- **O** = `requireOrganizationAccess` (org login in session org list, case-insensitive, else 404). `lib/api/server.ts:73-97`.
- **A** = `requireOrganizationAdmin` (O plus `viewerCanAdminister`, else 403). `lib/api/server.ts:99-120`.
- **I** = `resolveInstallationForOrganization` (org match, optional admin, then `github_installations` by org ID, else `GET /user/installations` sync). `lib/leaderboard/resolve-installation.ts:12-47`.
- **I+A** = I with `{ requireAdmin: true }`.
- **A*** = inline admin check `org.login === login` (case-sensitive).
- **D** = `requireDebugAccess` (none outside production, else flag + any session). `lib/auth/debug.ts:8-20`.

All routes use the Supabase service-role client. Only `leaderboard/score` and `leaderboard/recompute` set `maxDuration = 300`. No route sets `runtime`, `dynamic`, or `revalidate`.
